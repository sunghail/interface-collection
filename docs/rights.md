# 출처와 라이선스 기록

이 아카이브는 권리 상태가 서로 다른 자료를 포함할 수 있으므로, 저장소 전체에 하나의 라이선스를 임의로 적용하지 않습니다.

## My UI

작성자, 원본 프로젝트/commit, 재사용 허용 범위를 기록합니다.
직접 만든 코드에 적용할 라이선스가 정해졌다면 항목의 `licenses/LICENSE.txt`에 정확한 전문을 보관합니다.
미정이면 `rights.status=unverified`, `rights.license=UNSPECIFIED`로 두고 공개 재사용을 허용한다고 안내하지 않습니다.
외부 라이브러리·아이콘·폰트의 라이선스는 내 코드의 라이선스와 별도로 기록합니다.

## Reference UI

README와 metadata에 다음을 남깁니다.

- 원본 페이지, 제작자와 제작자 URL, repository, 확인한 commit/tag, 확인 날짜.
- 정확한 라이선스 이름 또는 SPDX 식별자(확인되지 않으면 UNKNOWN).
- 라이선스 근거 URL, 적용 범위(코드/이미지/폰트/디자인), 실제 보관한 파일.
- 캡처·복사본 보관 근거와 원본에 가한 수정.
- 참고한 이유, 차용하려는 패턴, 그대로 적용하면 안 되는 부분.

`rights.status`:
- `unverified`: 확인 전. 링크와 내 메모만 보관하고 이미지/코드는 미포함.
- `verified`: 해당 보관 범위의 근거 확인. 아래 표와 근거 URL/파일 필수.
- `permission-granted`: 별도 허가 확보. 허용 범위와 증거 위치를 기록.
- `restricted`: 제한 확인. 허용된 보관 범위를 명확히 적고 링크 위주로 유지.

license 없음/UNKNOWN을 공개 재사용 가능으로 해석하지 않습니다.
코드 라이선스만 확인한 경우 screenshot·상표·이미지도 같은 조건이라고 가정하지 않습니다.
README나 라이선스에 요구되는 저작권 표기·NOTICE가 있다면 함께 보관합니다.
개인 허가 메일 자체를 공개 저장소에 넣지 말고 공개 가능한 근거만 남깁니다.

`licenses/README.md` 기록 예시:

| 보관 파일/범위 | 제작자 | 근거 | 확인일 | 수정 |
| --- | --- | --- | --- | --- |
| 링크와 내 관찰 메모만 | 제작자 확인 예정 | 원본 URL | YYYY-MM-DD | 외부 파일 미복사 |

Reference를 참고해 직접 구현하면 별도 My UI 항목에 원본을 연결하고,
직접 작성한 부분과 가져온 부분을 구분합니다.
