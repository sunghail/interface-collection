# 검사 · 동기화 · 게시

## 검사 범위

아카이브 루트에서 실행한다. Python 3.10 이상 권장, 외부 패키지는 필요 없다.

```sh
python tools/build_catalog.py
python tools/build_catalog.py --check
```

첫 명령은 catalog를 쓰고 두 번째는 읽기 검사만 한다. 둘 중 실패하면 해당 원인을 해결한 뒤 다음 단계로 간다.
검증기가 존재한다고 원격 URL, 라이선스 판단, source 실행까지 검증된 것은 아니다.

- 항목/프로그램 README의 로컬 링크와 이미지 경로를 실제로 확인한다.
- 새 항목이 프로그램별·유형별·태그별 catalog에서 기대한 위치에 보이는지 확인한다.
- 업데이트 항목은 기존 ID·created·기록을 보존하고 이번 revision·updated를 갱신한다.
- 메인 README에 등록 현황을 하드코딩했다면 실제 목록과 일치시킨다. 모든 항목의 큰 이미지를 무한히 메인에 붙이지 않는다.
- 소스와 캡처에 실제 데이터·비밀값·개인 경로가 포함되지 않았는지 변경 범위만 검사한다. 발견한 비밀값을 로그로 출력하지 않는다.
- 필요 파일/lockfile/외부 고지가 빠지지 않았는지, preview가 설명한 방식으로 실행되는지 확인한다.
- 캡처 UI 테스트, 색인 검사, 소스 무결성 검사를 각각 구분해서 기록한다. 사용자 앱 전체 검증으로 표현하지 않는다.
- 준비한 파일의 크기를 확인한다. 대용량 자산은 무심코 커밋하지 않고 기존 보관 규칙을 따른다.

## Git 작업

게시 권한은 현재 사용자 요청과 이전에 합의한 범위를 기준으로 판단한다.
“여기에 UI를 올려줘”라면 검증한 UI 등록을 게시할 수 있다. “양식만 설명해”, “읽기만”, “로컬로 만들어”는 게시 지시가 아니다.

1. 현재 branch, remote, status를 확인하고 기존 사용자 변경을 보존한다.
2. 게시 전 fetch로 원격 변경을 확인한다. 원격이 앞서면 새 커밋을 읽고 현재 변경과 안전하게 통합한다. 불명확한 충돌에서는 다른 사람의 내용을 버리지 않는다.
3. 저장소의 CONTRIBUTING/AGENTS와 보호 브랜치 정책이 있으면 따른다. 현재 저장소는 main을 사용하지만 이것을 항상 직접 push하라는 영구 규칙으로 해석하지 않는다.
4. 이번 항목, 프로그램 README, 갱신한 catalog, 필요한 메인 문서만 명시적으로 stage한다. 다른 agent의 수정이 섞여 있을 수 있으므로 무조건 `git add .` 하지 않는다.
5. staged diff/파일 목록을 검토한다. `git diff --cached --check` 결과를 확인하고 새 문서의 오류를 고친다. 보존한 upstream 파일의 기존 whitespace를 정리한다는 이유로 snapshot을 몰래 바꾸지 않는다.
6. 원본 바이트 manifest가 있으면 Git index blob의 SHA-256까지 대조한다.
7. 의미 있는 commit을 만든 후 정해진 branch로 한 번 push한다. **push 종료를 확인하기 전 다른 commit/push를 겹쳐 실행하지 않는다.**
8. `git ls-remote origin refs/heads/<branch>`와 게시한 commit을 대조한다. 성공 로그 없이 게시 완료라고 말하지 않는다.
9. 인증 실패면 로컬 결과와 정확한 원인을 남긴다. 토큰/비밀번호를 채팅에 요구하지 않으며 원격 URL에 자격증명을 넣지 않는다. 동일 실패를 무한 재시도하거나 force push로 우회하지 않는다.
10. PR을 생성했다면 해당 환경의 artifact 첨부 도구가 있을 때 사용자 작업에 연결한다. PR 생성·게시·merge 여부를 구분한다.

Shell마다 종료 코드 처리가 다르다. PowerShell은 앞 명령 실패 후 다음 명령을 계속 실행할 수 있으므로 검사·commit·push 단계 사이에 `$LASTEXITCODE`를 확인한다.

## 다른 에이전트에게 전달할 최소 입력

다른 채팅에 메시지를 자동 발송하는 절차가 아니다. 사용자가 다음 내용을 전달하면 작업을 이어갈 수 있다.

```text
$archive-interface-ui를 사용해서 이 프로그램의 현재 UI를
https://github.com/sunghail/interface-collection에 양식대로 등록해줘.
원본 프로그램: [실제 경로 또는 현재 작업 프로젝트]
대상 버전/화면: [현재 버전 또는 지정한 범위]
기존 항목이 있으면 갱신하고, 실제 데이터 대신 합성 데이터로 캡처해줘.
소스와 실행법, 기술·권리 기록을 채우고 색인 검증 후 GitHub에 올려줘.
```

스킬이 해당 agent의 목록에 안 보이면 전체 SKILL.md 경로를 직접 전달한다. 이미 열려 있는 세션에서 새 스킬의 자동 검색 반영은 가정하지 않는다.
다른 컴퓨터에는 저장소의 `skills/archive-interface-ui` 폴더 전체를 해당 환경의 개인 skills 디렉터리로 설치하거나, 체크아웃 안의 SKILL.md를 직접 읽도록 전달한다.
